# Datasets

## Honesty policy

Everything in this repository that is used as data is labelled with its
provenance. Two categories exist, and they are never mixed up in reporting:

| Label | Meaning |
|---|---|
| `synthetic` | Generated by a script in this repo (e.g. espeak-ng text-to-speech). Freely redistributable, reproducible, but **not** real human speech. |
| `derived` | Built by transforming a real, explicitly licensed corpus (e.g. AMI). The licence and citation are recorded in `datasets/README` files. |

No dataset in this project is presented as a real-world corpus unless it
genuinely is one. Synthetic examples are always described as synthetic.

## Layout

```
datasets/
├── raw/        Source material as obtained or generated (never edited by hand)
├── processed/  JSONL produced by training/prepare_dataset.py
└── README.md   this file
```

## 1. Sample meeting recording (synthetic)

`datasets/raw/sample_meeting/` is produced by:

```bash
cd backend
.venv/bin/python scripts/make_sample_recording.py
```

It contains:

* `sample_meeting.mp4` — a 53 s video container wrapping the audio, mimicking
  a Google Meet export.
* `sample_meeting_16k.wav` — the 16 kHz mono audio the pipeline extracts.
* `ground_truth.json` — the exact text that was spoken, so Word Error Rate can
  be computed against a trustworthy reference.

Why generate rather than download: no public meeting corpus ships with a
transcript that can be freely redistributed, and inventing one silently would
be dishonest. Generating audio locally gives a reproducible test asset with a
known reference text.

**Limitation to state in the report:** espeak-ng is a formant synthesiser.
Its output is cleaner and more evenly paced than human conversation, and it has
no overlapping speech, no disfluencies and no room noise. Accuracy measured on
it will be optimistic compared with real meetings.

## 2. Meeting-minutes dataset (synthetic, for fine-tuning)

`datasets/raw/meeting_minutes/` holds transcript → structured-minutes pairs
used to fine-tune the extraction model (see `training/`). These are authored
examples covering academic and business meeting scenarios. They are labelled
synthetic and must be described as authored for this project, not collected
from real organisations.

## 3. Public corpora that could be incorporated

These are the credible options if a real-speech evaluation is wanted. **None
are downloaded by this repo** — each requires accepting a licence and citing
the source. Do that manually and record the citation here.

* **AMI Meeting Corpus** — <https://groups.inf.ed.ac.uk/ami/corpus/>
  ~100 hours of real multi-speaker meetings with manual transcripts and
  `scenario`/`mix` headset recordings. The standard benchmark for meeting ASR.
  Free for research use; cite Carletta et al. (2005).
* **ICSI Meeting Corpus** — <http://groups.inf.ed.ac.uk/icsi/>
  ~70 hours of real meetings with transcripts and speaker diarisation.
* **LibriSpeech** — <https://www.openslr.org/12>
  Although read speech rather than meetings, it is convenient for a quick
  WER baseline since it is public domain and widely used.
* **Virtual Meeting Platform transcript exports** — a Teams/Meet/Zoom
  transcript export from a real meeting *the user has permission to use* is
  the most relevant data of all. It is not redistributable, so keep it out of
  version control and describe it only in aggregate in any report.

### Recommended evaluation plan

1. Use the synthetic sample for pipeline smoke tests and CI, because it is
   reproducible and needs no licence.
2. Use a small subset of **AMI** (a few `scenario` meetings) for the reported
   WER and information-extraction metrics, citing it properly.
3. Clearly separate the two sets of numbers in the report — never blend
   synthetic and real-audio results into a single figure.
